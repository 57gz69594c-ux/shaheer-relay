WHAT v5.6.0 MUST DO TO CLOSE THIS GAP
=========================================================================

TIER 1 — Eliminate external API dependency (biggest single improvement):

  Current bottleneck: Every liquidation attempt queries Kyberswap or Velora
  over HTTP. Each call takes 1–10+ seconds and we're rate-limited to a few
  hundred per minute.

  Solution: DIRECT ON-CHAIN DEX POOL ROUTING. Read Uniswap V3/V2,
  SushiSwap, PancakeSwap, Curve pool states via multicall in a single RPC
  batch. Compute the swap output locally using the constant-product or
  concentrated-liquidity formula. No HTTP API. No rate limits. No timeouts.

  Target: Quote any token pair in < 50 ms via RPC multicall.

TIER 2 — WebSocket oracle subscription (detect opportunities instantly):

  Current: We poll oracle prices every 5–9 seconds per chain.

  Solution: Subscribe to Chainlink oracle Update events and Morpho/Aave
  oracle calls via WebSocket. The moment a price update transaction is
  confirmed, we know about it in < 500 ms instead of waiting for the next
  poll cycle.

  Target: Oracle detection in < 500 ms after block confirmation.

  BEYOND THAT: Subscribe to the MEMPOOL (pending transactions). See oracle
  updates BEFORE they're mined. This is how MEV bots achieve same-block
  execution — they see the price change in the mempool, build a liquidation
  transaction, and bundle both together via Flashbots.

  Target: Oracle detection BEFORE block confirmation (0 ms effective).

TIER 3 — Pre-computed routing table (zero-latency route lookup):

  Current: We discover the route after finding the opportunity.

  Solution: Maintain a hot routing table for every collateral→debt token
  pair across all monitored markets. Update it every block using the
  on-chain pool state reads from Tier 1. When a position becomes
  liquidatable, the route is already known.

  Target: Route lookup in < 1 ms (memory read, no computation needed).

TIER 4 — Local simulation (eliminate RPC round-trip for simulation):

  Current: We simulate via remote Chainstack RPC. Each call adds 1–2
  seconds of network latency.

  Solution: Run a local execution client (Reth or Geth) on the VPS. Fork
  the latest state locally. Simulate the liquidation transaction against
  the local fork in < 50 ms with zero network latency.

  Target: Simulation in < 50 ms.

TIER 5 — Private transaction submission (prevent frontrunning):

  Current: We submit to the public mempool. MEV bots see our transaction
  and can frontrun it.

  Solution:
  - Ethereum: Flashbots eth_sendPrivateTransaction or MEV-Share bundles.
    Our tx never enters the public mempool. Block builders include it
    directly. We can even bundle our liquidation with the oracle update.
  - Arbitrum/Base/Optimism: Submit directly to the sequencer endpoint.
    L2 sequencers process transactions in order of arrival — first in,
    first executed. Latency to the sequencer is everything.

  Target: Private submission with < 100 ms to block builder/sequencer.

TIER 6 — Same-block execution (the ultimate edge):

  Combine all tiers:
  1. See oracle update in mempool (before it's mined)
  2. Route already pre-computed
  3. Build liquidation tx in < 10 ms
  4. Simulate locally in < 50 ms
  5. Bundle with Flashbots: oracle update + our liquidation = same block

  Target: SAME-BLOCK execution. The opportunity never exists publicly
  because we execute it in the same block it's created.
